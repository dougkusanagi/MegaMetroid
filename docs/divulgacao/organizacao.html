Organização do canal de ports

Resumo das recomendações para roteiros, vídeos e divulgação dos ports. Novembro de 2026.

Resumo

  • Roteiros, agenda e textos: um repositório GitHub separado (ex.: devlog-ports), para todos os ports, não só o MegaMetroid.
  • Vídeos brutos, projetos de edição e exportações: OneDrive (ou HD externo + OneDrive para os finais). Git não serve para arquivos grandes.
  • Repo do MegaMetroid: fica só com o código. Ele aponta para o devlog no README, e o devlog lê o CHANGELOG.md dele para gerar pautas.
  • Um vídeo por marco do plano, não por tempo. Cada vídeo longo gera de 3 a 5 cortes, postados um por dia.

Não use Git LFS para vídeo: a cota grátis do GitHub é pequena e o versionamento de vídeo não traz ganho.

Um GitHub Project (quadro) com colunas Ideia → Roteiro → Gravado → Editado → Agendado → Publicado dá visão rápida. Cada vídeo é uma issue; os cortes são itens da issue.

Os roteiros já escritos estão em MegaMetroid/docs/divulgacao/roteiros.md. Depois que o repo existir, eles podem ir para lá e sair do MegaMetroid.

Fluxo por vídeo

  1. Pauta: ao fechar um marco do docs/PLANO.md, peça ao Claude uma pauta a partir do CHANGELOG.md desde o último vídeo.
  2. Roteiro: preencha o template. Escreva o gancho de cada corte já no roteiro, para não cortar depois "no escuro".
  3. Gravação: grave cada cena isolada, em 60 fps, com captura limpa (sem HUD do emulador). Grave em vertical ou com espaço para recorte 9:16.
  4. Edição: vídeo longo primeiro; os cortes saem dos mesmos clipes.
  5. Agendamento: YouTube Studio e TikTok agendam nativo; no X, use o agendamento do próprio site. Registre os links em cortes.md.
  6. Revisão (uma semana depois): anote visualizações e retenção em videos/.../metricas.md e o que repetir.

Ideias além do que você já faz

Formato

  • Comparação lado a lado SNES × Mega Drive como marca visual do canal. É o tipo de corte que mais circula nesse nicho.
  • Série técnica "Mega Drive limits": divisão no 68000, 80 sprites, VRAM, DMA, 3 canais PCM no XGM2. Atrai devs de homebrew e não depende só de um jogo.
  • "Before / after" de 15 s para cada correção visível (pulo, câmera, animação).
  • Devlog escrito curto (post no GitHub Pages, itch.io devlog ou Bluesky) com GIFs: bom para quem não vê vídeo e para buscadores.
  • Making of com IA: um vídeo honesto sobre como os agentes ajudam (medição, testes no BlastEm, revisão). É um tema com público próprio.
  • Lives curtas de desenvolvimento, gravadas e cortadas depois.

Ferramentas

  • OBS com cenas prontas: jogo 16:9, jogo 9:16 com moldura, lado a lado.
  • DaVinci Resolve (grátis) para o longo; legendas automáticas do CapCut ou do próprio YouTube para os cortes.
  • Templates de miniatura com a mesma fonte, layout e cor, para o canal ter cara reconhecível.
  • Uma página "links" (GitHub Pages) com canal, redes e a lista dos ports.

Comunidade

  • Discord do SGDK, SpritesMind, r/SEGAGENESIS, r/megadrive, r/retrogaming, Bluesky (#SGDK). Leia as regras de autopromoção de cada um.
  • Participe antes de divulgar: responda dúvidas técnicas e compartilhe soluções (ex.: a armadilha do canal PCM 4). Isso gera mais alcance que só postar links.
  • Contate canais de notícias retro e homebrew com um e-mail curto e um vídeo de 30 s.

Riscos

  • Propriedade intelectual: o MegaMetroid usa recursos extraídos de Super Metroid. A Nintendo costuma pedir a retirada de fan games, e a exposição aumenta essa chance. Não distribua a ROM nem os recursos, e não ponha o código público com esses recursos sem avaliar isso.
  • Monetização: ganhar dinheiro com o conteúdo (monetização do canal, Patreon, doações ligadas ao port) aumenta o risco. Se quiser monetizar, faça isso com conteúdo técnico ou com projetos próprios.
  • Diversifique: um projeto homebrew original (mesmo pequeno) em paralelo dá ao canal um conteúdo que ninguém pode derrubar e que você pode vender ou distribuir.
  • Automação de postagem: X, TikTok e Reddit restringem bots. Use o agendamento nativo; com o navegador, só com você logado e confirmando cada post.
